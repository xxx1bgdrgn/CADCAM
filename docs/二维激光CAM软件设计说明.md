# 二维激光 CAM 软件设计说明

## 1. 产品目标

开发一款独立的 Windows 二维激光 CAM 桌面软件，交付可双击运行的 EXE。首版覆盖十种基础图元绘制、图形组合与解组、DWG/DXF 导入、零件和板材管理、排样结果查看、逐图形工艺、刀路预览、G 代码文件导出和工程保存。

一次典型的操作流程是打开图纸进入底图，定义零件和板材，查看排样结果，设置或检查补偿与引线，预览刀路并导出 G 代码。保存工程后，重新打开可以恢复图形、工艺、板材和排样。

## 2. 技术栈与模块职责

以 **C++ + Qt 6 Widgets + OCCT** 为主线，用 CMake 和 MSVC 构建 Windows x64 程序。Qt 管理窗口、工具栏、列表和属性面板。OCCT 负责二维几何、画布显示与选择、轮廓运算和工程持久化。CAM 代码负责把逐图形工艺转换成可预览和可导出的加工动作。

| 模块 | 选型 | 职责 |
| --- | --- | --- |
| 桌面界面 | Qt 6 Widgets | 工具栏、列表、工艺面板、文件对话框和快捷键 |
| CAD 主内核 | OCCT | 维护曲线和轮廓，支持平面几何运算，提供显示和选择 |
| DWG/DXF 导入 | 待样图验证后选择 | 用独立的导入模块读图，把图元转成工程使用的 OCCT 几何 |
| 刀路与 G 代码 | C++ CAM 逻辑和后处理器 | 应用补偿和引线，组织切割与空移动作，按控制器格式输出 |
| 撤销重做 | Qt `QUndoStack` / `QUndoCommand` | 记录工程编辑，应用和回退变更 |
| 工程文件 | OCAF `BinOcaf`，自定义 `.camproj` 扩展名 | 保存几何、工艺、三个列表及其关联 |
| Windows 发布 | CMake + MSVC x64 | 构建 EXE 并部署 Qt、OCCT 和读图库的运行依赖 |

[Qt Widgets 文档](https://doc.qt.io/qt-6/qtwidgets-index.html) · [OCCT 构建文档](https://occt3d.com/dev/doc/overview/html/build_upgrade__building_occt.html) · [Qt Windows 部署](https://doc.qt.io/qt-6/windows-deployment.html)

### DWG/DXF 导入选型

OCCT 官方提供单独授权的 DXF 导入导出组件。当前官方格式清单未列出 DWG。保留直接打开 DWG 的需求时，可以选 ODA Drawings SDK 或 Autodesk RealDWG 读取 DWG/DXF，并在导入后统一转换为 OCCT 几何。若工作流程允许先把 DWG 另存为 DXF，则可评估只接入 OCCT 官方的 DXF 组件。

导入首版按下表识别对应的 DWG/DXF 图元。对带圆弧的多段线、椭圆弧、文字、块引用及嵌套块，需要用实际图纸核对变换、单位和图元完整性。遇到影响加工的图元无法读取时，导入结果应显示具体问题。

[OCCT 格式清单](https://github.com/Open-Cascade-SAS/OCCT/discussions/1210) · [OCCT DXF 组件](https://occt3d.com/components/dxf-exchange/) · [ODA Drawings SDK](https://www.opendesign.com/products/drawings) · [Autodesk RealDWG](https://aps.autodesk.com/developer/overview/realdwg-api)

### 基础图元和绘图工具

首版提供以下十种绘图工具。手绘与导入使用同一套图元数据，每种图元都能进入底图并随工程保存和恢复。

| 图元 | DWG/DXF 中的常见类型 | 图元数据 |
| --- | --- | --- |
| 点 | `POINT` | XY 坐标，可作为定位和捕捉参考 |
| 直线段 | `LINE` | 起点和终点，对应一条 OCCT 边 |
| 圆弧 | `ARC` | 圆心、半径、起终点及弧段方向，对应一条圆弧边 |
| 圆 | `CIRCLE` | 圆心和半径，表示完整的闭合圆轮廓 |
| 矩形 | 闭合多段线或相连的直线 | 四条直线组成的闭合轮廓 |
| 圆角矩形 | 带弧的闭合多段线或相连的直线和圆弧 | 圆角半径和闭合轮廓，通常由四条直线和四段圆弧构成 |
| 文字 | `TEXT`、`MTEXT` | 内容、插入点、字高、字体、对齐和旋转角度 |
| 椭圆 | `ELLIPSE` | 中心、长短半轴和长轴方向，表示完整的闭合椭圆 |
| 椭圆弧 | `ELLIPSE` 的局部曲线 | 椭圆参数、弧段的起止参数及方向 |
| 二维多段线 | `LWPOLYLINE`、二维 `POLYLINE` | 按顺序连接的直线段和圆弧段，以及开口或闭合状态，对应一条 `TopoDS_Wire` |

手绘矩形和圆角矩形各产生一个闭合轮廓 `Shape`，可以给整圈设置一次补偿和引线。从文件读到独立的散线时，可以通过拼接工具在端点公差内生成有序边链。

导入带弧多段线时，按凸度（`bulge`）还原圆弧段，并保留闭合标志。导入 `ELLIPSE` 时按参数范围区分完整椭圆和椭圆弧。保存与编辑时保留原始曲线，画布和刀路可以按各自需要求值。 [Autodesk 实体类型](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-7D07C886-FD1D-4C0C-A7AB-B4D21F18E484.htm) · [Autodesk 多段线字段](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-748FC305-F3F2-4F74-825A-61F04D757A50.htm) · [Autodesk 椭圆字段](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-107CB04F-AD4D-4D2F-8EC9-AC90888063AB.htm) · [OCCT 椭圆弧示例](https://occt3d.com/dev/doc/overview/html/occt__tutorial.html)

首版建议点用于定位，文字保存为可编辑对象。文字需要参与切割时，先显式转成字形轮廓，再对轮廓设置工艺。导入和重新打开文字时，缺少原字体应提示替代字体。应用内外补偿前校验加工轮廓是否闭合。

## 3. 界面布局和操作

参考截图里的工作区分工，保留中央画布为主区域。截图中左侧显示零件列表，右侧排版列表里有一项「草图」，顶部提供「板材清单」入口。本软件采用独立的界面布局，右侧用标签页提供排样结果和板材两个列表。

| 区域 | 内容与交互 |
| --- | --- |
| 顶部工具栏 | 打开或保存工程、DWG/DXF 导入、绘图、组合与解组、工艺、排样、预览和导出 |
| 左侧零件列表 | 显示零件名称、缩略图和尺寸。双击切换到该零件的视图 |
| 中央画布 | XY 正交俯视，支持选择、缩放和平移。显示当前视图的原图、刀路和加工序号 |
| 右侧排样结果标签 | 默认打开。首项固定为「底图」，后面是正式排样，双击任意一项切换视图 |
| 右侧板材标签 | 显示板材列表。双击板材只查看该板材的边界及尺寸 |
| 工艺面板 | 显示选中图形的工艺列表，支持添加、编辑和删除工艺 |

画布或列表里的当前选中状态用于查看和编辑。若提供「参与排样」勾选框，勾选状态独立保存。排样结果页的数量统计只计算正式排样，「底图」始终显示在首位。

## 4. 工程内存结构

`Project` 直接持有三个有序列表。底图实际存放在 `nestingResults[0]`，保存、打开和增删正式排样时都遵循这个约定。

| 集合 | 每项保存什么 |
| --- | --- |
| `parts` 零件列表 | 零件 ID、名称、按序保存的图形列表。一个零件可以由外框、孔和其他图形组成 |
| `sheets` 板材列表 | 板材 ID、名称，以及边界或尺寸 |
| `nestingResults` 排样结果列表 | 第 0 项是底图，直接保存图形列表。第 1 项起是正式排样，保存板材 ID 和零件摆放列表 |

每个 `Shape` 有稳定 ID，可以表示单个图元，也可以表示群组。单个图元保存自己的原始几何或文字属性，以及该图元的工艺列表。群组保存有序的子 `Shape`，成员继续保留各自的 ID、几何和工艺。底图与零件内部按列表顺序组织顶层 `Shape`。

### 图形组合与解组

- **组合**。在同一视图选中多个图形，创建一个群组 `Shape`。群组在原列表占一项，放在首个被选中图形的位置，成员维持原有相对顺序。
- **编辑**。选中群组可以整体移动或旋转。选择组内成员时，可以编辑该成员的几何和工艺。首版建议对群组执行工艺设置时，将可用工艺批量应用到选定的可加工成员。
- **解组**。用群组的成员按顺序替换群组项，保留各成员当前位置、角度和工艺。组合、解组以及整组移动各记为一条可撤销的工程操作。

例如，把一个外框和两个圆孔组合后，拖动时可以一起移动。生成刀路时，三个轮廓依然分别使用自己的补偿、引线和走向。需要把相连的散线接成一条加工轮廓时，使用拼接工具生成闭合或开口边链。 [OCCT 边链构建](https://occt3d.com/dev/doc/refman/html/class_b_rep_builder_a_p_i___make_wire.html)

每条正式排样的摆放记录保存实例 ID、零件 ID、平移位置和旋转角度。同一个零件放置两次，就产生两条不同的摆放记录。画布用同一零件的几何分别应用定位变换，显示各自的位置。点击具体图形时，通过实例 ID 和源图形 ID 一起定位。

打开 DWG/DXF 创建新工程时，零件和板材列表初始为空，排样结果列表只有底图。把导入的全部图形放进底图，然后立即激活该视图。生成的正式排样追加到索引 1 起的位置，可以单独增删和重排。

## 5. CurrentZone 和画布渲染

`CurrentZone` 是当前画布的工作区，保存视图类型、来源 ID 和该视图的可渲染数据。三个列表是工程数据来源。点击画布产生的编辑，通过来源 ID 和图形 ID 写回对应记录，再刷新 `CurrentZone`。

| 当前视图 | 放入 `CurrentZone` 的内容 |
| --- | --- |
| 底图 | `nestingResults[0]` 内的全部图形 |
| 零件 | 指定零件的外框、孔和其他图形，使用零件坐标 |
| 板材 | 指定板材的边界与尺寸显示数据 |
| 正式排样 | 对应板材，以及按摆放位置和角度变换后的各零件图形 |

双击统一走同一条处理流程。

```text
双击列表项 → 读取来源数据 → 构建并替换 CurrentZone
          → 清理旧显示与选中状态 → 渲染新视图 → 适配画布
```

Qt 承接窗口与列表交互。OCCT 的 `V3d_View` 固定为 XY 正交俯视，`AIS_InteractiveContext` 负责画布中的图形显示、选取和高亮。群组进入 `CurrentZone` 后按成员生成渲染项，渲染项保留群组 ID 和成员 ID，支持整体选中和定位成员。原始轮廓、补偿轮廓、引线、空移和加工序号使用可区分的显示样式。选中图形后，工艺面板显示关联的工艺列表。

[OCCT 可视化文档](https://occt3d.com/dev/doc/overview/html/occt_user_guides__visualization.html) · [AIS 选择接口](https://occt3d.com/dev/doc/refman/html/class_a_i_s___interactive_context.html)

## 6. 每个图形的工艺列表

此处的工艺是**刀路几何设置**，例如补偿、引入线和引出线。进给、功率和穿孔延时等机床参数按导出配置处理。

| 工艺 | 保存的参数 |
| --- | --- |
| 补偿 | 补偿方向和单边偏移距离。实测切缝宽为 0.20 mm 时，示例单边偏移为 0.10 mm |
| 引入线 | 直线或圆弧类型、长度以及该线型所需的角度或半径等参数 |
| 引出线 | 直线或圆弧类型、长度以及该线型所需的角度或半径等参数 |
| 切入位置和走向 | 用户设置时，保存起点定位与顺逆时针方向，供生成刀路时使用 |

首版建议补偿、引入线和引出线各最多一条。再次选择同一工艺时编辑已有项。可加工图元的工艺为空时，按原始轮廓生成刀路。

**工艺的添加顺序与求解次序可以不同。** 例如先添加引线、后添加补偿时，仍先偏移原始轮廓，再在补偿轮廓上定位切入点并接上引线。用户反复编辑补偿时，每次都从原始几何重算。

## 7. 排样、刀路预览和 G 代码

排样模块根据所选零件和板材生成摆放记录。排样结果保存具体位置和角度，打开工程时按原摆放恢复。自动排样具体采用哪种算法，留待板材约束、图纸样本和首版范围明确后选定。

生成加工路径时，按选定加工视图的顺序遍历图形，遇到群组按保存的成员顺序展开。每个可加工成员分别生成刀路。在正式排样中，先取得零件的轮廓和工艺，再应用该摆放实例的变换。首版可按摆放列表展开各零件，再按各零件内部的图形列表顺序生成刀路。整张板上跨零件的手动排序规则仍待确认。

```text
原始轮廓 + 逐图形工艺
  → 计算补偿轮廓
  → 定位切入点并确定走向
  → 拼接引入线、轮廓、引出线
  → 按加工顺序连接空移
  → 同一份加工动作交给画布预览和 G 代码后处理
```

例如半径为 10 mm 的圆孔，内补偿 0.10 mm 得到半径 9.90 mm 的刀路。引线接到补偿后的轮廓。直线和圆弧保留其几何类型。椭圆和椭圆弧保留在原始图元里，当控制器只接受直线和圆弧运动时，按设定的几何误差逼近成可执行的线段或圆弧段。预览使用同一份逼近后的加工路径，保证显示和导出一致。

后处理器负责单位、坐标方式、运动指令和机床参数映射。首版以预览和文件导出为目标，实际机床所需的开关光、功率和穿孔指令由目标控制器型号确定。 [LinuxCNC G 代码参考](https://www.linuxcnc.org/docs/html/gcode/g-code.html)

## 8. 撤销和重做

每个打开的工程使用一套 `QUndoStack`。每条 `QUndoCommand` 通过稳定 ID 定位源数据，保存恢复该次编辑所需的旧值、新值或原列表位置。双击切换视图、选择、缩放和平移属于画布操作。 [Qt 撤销栈](https://doc.qt.io/qt-6/qundostack.html) · [Qt 撤销命令](https://doc.qt.io/qt-6/qundocommand.html)

| 编辑 | 命令记录 |
| --- | --- |
| 新增、删除图形 | 完整图形、所属列表及插入位置 |
| 修改几何或工艺 | 目标图形 ID 与修改前后值 |
| 组合、解组或整组变换 | 群组与成员的 ID、原有层级和列表位置，以及变换前后值 |
| 调整顺序 | 对应列表及调整前后顺序 |
| 移动一个摆放实例 | 实例 ID 与移动前后的位置、角度 |
| 一次生成多个排样结果 | 整批结果与插入位置，重做还原同一批结果 |

支持连续撤销、连续重做和交替执行。撤销后如果做了新编辑，Qt 撤销栈从该位置开始记录新操作，原有的后续重做记录被替换。一次拖拽按一次工程编辑记录。

切换视图后按撤销，仍回退最近一次工程编辑。例如在零件视图修改引线后切到排样，撤销会恢复零件原来的引线。若该零件出现在当前排样中，同时刷新排样的显示。撤销导致正在查看的排样被删除时，回到索引 0 的底图。

## 9. 自定义工程文件

用自己的 `.camproj` 扩展名和工程结构，内部采用 OCAF `BinOcaf` 二进制读写。OCAF 保存原始几何与应用属性，工程文件包含恢复三个列表所需的全部数据。 [OCAF 文档](https://occt3d.com/dev/doc/overview/html/occt_user_guides__ocaf.html) · [BinOcaf 读写接口](https://occt3d.com/dev/doc/refman/html/class_bin_drivers.html)

```text
零件加工.camproj
├─ 工程信息（应用格式版本、单位）
├─ 零件列表（按顺序保存）
│  └─ 零件记录（ID、名称、图形列表）
│     └─ 图形记录（ID、图元数据与工艺，或群组的有序成员）
├─ 板材列表（按顺序保存）
│  └─ 板材记录（ID、名称、边界或尺寸）
└─ 排样结果列表（按顺序保存）
   ├─ [0] 底图（全部原始图形、群组及各成员的工艺）
   └─ [1...] 正式排样（板材 ID、摆放列表）
      └─ 摆放记录（实例 ID、零件 ID、位置、旋转角度）
```

保存时写出三个列表当前的工程状态，覆盖已有文件时先完成临时文件的写入，再替换目标文件。保存成功后将撤销栈标记为已保存。首版撤销历史留在当前工程会话。

打开时先恢复和校验三个列表，包括格式版本、索引 0 是否为底图、图元类型和群组成员顺序，以及排样引用的零件与板材是否存在。通过后切换到读入的工程，构建底图 `CurrentZone` 并渲染。画布数据和刀路从恢复后的工程生成，原始 DWG/DXF 文件移走后也可以重新打开已保存的工程。

| 分别打开 DWG 和 DXF | 模型几何进入底图，右侧只有底图一项。多段线圆弧和闭合状态、椭圆弧范围及文字属性在导入后保持 |
| 双击视图条目 | 底图、零件、板材和正式排样分别显示各自数据，选中对象与工艺面板对应 |
| 同一零件摆放两次 | 两份按各自位置和角度显示，可以分别选中 |
| 设置圆孔补偿和引线 | 预览保留原始轮廓，显示正确的补偿刀路和引线，导出顺序与预览一致 |
| 连续或交替撤销重做 | 每一步恢复准确的数据。切换视图后仍沿同一条工程历史执行 |
| 保存、关闭、移走原始 CAD 文件后重新打开 | 三个列表的条目和顺序、图元数据、群组层级与成员顺序、逐图形工艺及排样摆放均恢复 |
| Windows 发布 | 在干净的目标环境启动 EXE，并完成绘图、导入、保存和导出 |
